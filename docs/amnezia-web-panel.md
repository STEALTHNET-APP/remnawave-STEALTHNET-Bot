# Amnezia Web Panel (issue #96)

Интеграция предназначена для [PRVTPRO/Amnezia-Web-Panel](https://github.com/PRVTPRO/Amnezia-Web-Panel), а не для одноимённых сторонних API. Она не заменяет прямые AmneziaWG-ноды STEALTHNET.

## Совместимость API

В upstream-коммите `6236bf927b1b7612a7a1231a8eca33420c66e3ee` есть несоответствие документации: `_check_admin` принимает Bearer-токен, а `get_current_user` принимает только сессию браузера. Создание/удаление/отключение пользователей и выдача конфигов не работают с API-токеном и возвращают 403.

До исправления upstream нужен патч `patches/amnezia-web-panel-token-auth.patch` во внешней панели. Он использует существующую проверку хеша токена, его владельца, роли и блокировки; не отключает аутентификацию. Установщик `scripts/patch-amnezia-web-panel.py` работает без сторонних Python-зависимостей:

```sh
python3 /path/to/STEALTHNET/scripts/patch-amnezia-web-panel.py /path/to/Amnezia-Web-Panel/app.py
python3 /path/to/STEALTHNET/scripts/patch-amnezia-web-panel.py /path/to/Amnezia-Web-Panel/app.py --apply
```

Первая команда только проверяет совместимость. Вторая делает резервную копию `app.py.stealthnet-token-auth.*.bak`, применяет изменение атомарно и сохраняет права файла. Повторный запуск ничего не меняет. Неизвестная версия будет отклонена. Затем перезапустите внешнюю панель. Для отката остановите панель, восстановите `app.py` из указанной резервной копии и запустите снова.

Если внешняя панель работает из Docker-образа, исправьте `app.py` в исходниках и пересоберите её образ; правка внутри запущенного контейнера пропадёт при его пересоздании. STEALTHNET не изменяет чужую установку по API-токену автоматически.

Также можно применить обычный diff. Перед этим сохраните копию `app.py`. Для исходников указанного коммита: `git apply --check /path/to/amnezia-web-panel-token-auth.patch`, затем `git apply /path/to/amnezia-web-panel-token-auth.patch` и перезапуск панели. Не применяйте патч вслепую к другой версии. После обновления внешней панели проверяйте совместимость заново.

При добавлении ноды STEALTHNET проверяет доступ к API, в том числе к методу, который требует полной поддержки токенов. Неподдерживаемая панель не сохраняется как рабочая.

## Подключение

1. Во внешней панели добавьте сервер и установите AWG, WireGuard или Xray. Настройте часовой пояс процесса внешней панели **UTC**: её API принимает дату без часового пояса.
2. Создайте API-токен от администратора в настройках внешней панели.
3. В STEALTHNET откройте «Sing-box / AmneziaWG», добавьте ноду с вариантом «Amnezia Web Panel» нужного протокола.
4. Укажите HTTPS-адрес, токен, номер сервера из адреса `/server/0` и имя протокола: `awg`, `awg2`, `awg3`, `awg_legacy`, `wireguard`, `xray` или экземпляр AWG/Xray вроде `awg2__2`. WireGuard использует единственный экземпляр `wireguard`.
5. Создайте тариф того же типа: `AWP_AWG`, `AWP_WIREGUARD` либо `AWP_XRAY`. Он продаётся через существующий магазин доступов, кабинет и бот.

Для получения постоянного UID сервера используется штатный read-only API экспорта JSON. Внешняя панель пока не предоставляет отдельного JSON-метода инвентаризации всех серверов. SSH-пароли и прочие поля экспорта не сохраняются и не возвращаются в интерфейс. При перестановке серверов номер определяется повторно по сохранённому UID.

API-токен хранится только на backend, не возвращается в деталях ноды или кабинете. Его можно заменить в редактировании ноды. HTTP разрешён только для loopback; удалённый API требует HTTPS с доверенным сертификатом. Перенаправления запрещены.

## Доступы

Каждому купленному слоту соответствует отдельный пользователь с ролью `none` и одно подключение во внешней панели. Пользователи интеграции имеют уникальное имя и маркер владельца; чужие пользователи не изменяются.

После оплаты создаётся доступ с лимитом трафика и сроком тарифа. AWG и WireGuard выдаются файлом `.conf` и QR в кабинете; бот отправляет `.conf`. Xray выдаётся ссылкой. Обычная покупка создаёт новый доступ.

В кабинете, во вкладке «Мои доступы», клиент может продлить существующий слот с баланса. Кнопка в боте открывает этот раздел. При нехватке средств можно пополнить баланс подключённым способом оплаты. Истёкшие и ожидающие синхронизации доступы также видны в кабинете.

Цена продления одного слота — текущая цена его тарифа, делённая на число слотов с округлением вверх до копейки, с учётом персональной скидки. Срок добавляется к текущему сроку или к моменту оплаты, если доступ истёк. Пакет трафика добавляется к прежнему лимиту; безлимит остаётся безлимитом. Конфиг и ключи сохраняются. Изменение цены перед оплатой требует повторного подтверждения.

Списание, платёж и запись продления создаются в одной транзакции. Повтор того же запроса не списывает деньги второй раз. Если внешняя панель недоступна, продление остаётся оплаченным и применяется при восстановлении связи. Возврат платежа продления убирает только соответствующий срок и трафик, сохраняя первоначальную покупку и другие продления. Администратор также может изменить срок в деталях ноды; эта корректировка сохраняется при дальнейшей синхронизации.

Обновление требует миграции `20261019170000_amnezia_web_renewal`. Перед обновлением сохраните базу. Для продлений добавляются отдельный журнал и служебные поля слотов; существующие покупки сохраняются.

Синхронизация выполняется при запуске API, после покупки и раз в минуту. Блокировка клиента, истечение срока, исчерпание трафика и отключение ноды отключают удалённого пользователя. Возврат/отмена оплаты и отзыв доступа удаляют его подключения и пользователя. Удалённые локальные клиенты очищаются через сверку помеченных удалённых пользователей. При недоступности внешней панели операции повторяются; немедленное отключение VPN через недоступный API не гарантируется.

Повторная обработка оплаты использует те же слоты. Если ответ на создание подключения потерян, следующая попытка выдерживает паузу и ищет созданный peer по уникальному имени, прежде чем создавать новый. Не меняйте вручную имена и маркеры управляемых пользователей во внешней панели.

Поддерживаются AWG/WireGuard/Xray как клиентские VPN-доступы. MTProxy, AdGuard Home и управление установкой сервисов через STEALTHNET в эту интеграцию не входят.

## Проверка

Контракт проверяется с настоящими FastAPI-маршрутами указанного upstream-коммита, отдельной PostgreSQL и тестовым SSH-адаптером. Фикстура `backend/tests/amnezia-web-panel-fixture.py` требует `AWP_SOURCE` (клон upstream), `AWP_QA_DATA` (отдельный временный JSON) и зависимости внешней панели. Она слушает только `127.0.0.1:5056` и не должна использоваться в production.

Тест backend: после сборки, из каталога `backend`, `DATABASE_URL=<отдельная тестовая база> node --experimental-vm-modules tests/amnezia-web-postgres.mjs`. В том же окружении запускается `tests/amnezia-web-renewal.mjs`: транзакции продления, повторные и параллельные запросы, возвраты, скидки, истечение срока и восстановление связи. Запускайте эти тесты последовательно, с отдельной базой и заново запущенной фикстурой для каждого набора. `tests/amnezia-web-balance.mjs` проверяет атомарность списания с созданием платежа. Тесты с имитацией SSH не заменяют проверку реального VPN-туннеля.

Дополнительно проверены настоящие AWG 2.0, WireGuard и Xray REALITY через менеджеры внешней панели и отдельные Docker-контейнеры: выдача конфига после оплаты, передача 100 КиБ через каждый туннель, блокировка, восстановление доступа и отзыв после возврата оплаты. Для WireGuard и Xray также проверены платное продление с сохранением конфигурации и передача данных после продления. В браузере проверено продление через настоящий API с отдельной тестовой базой.

Создание WireGuard выполняется через штатный `/api/servers/{id}/connections/add` с привязкой пользователя: пользовательский метод создания подключения в проверенной версии upstream передаёт WireGuard-менеджеру несовместимые аргументы. Повтор после потери ответа ищет существующее подключение по имени и не создаёт дубликат.
