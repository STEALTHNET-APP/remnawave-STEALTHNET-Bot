# AmneziaWG

Панель управляет отдельными AmneziaWG-нодами: создаёт доступы после оплаты, выдаёт `.conf` и QR-код, отключает истёкшие, заблокированные и отозванные доступы, учитывает трафик. В Telegram файл можно получить в разделе «Мои доступы».

## Установка

1. Включите раздел Sing-box / AmneziaWG в настройках кабинета, если он скрыт.
2. Откройте Sing-box / AmneziaWG → Ноды → Добавить. Выберите `AMNEZIAWG`, укажите публичный IP/домен сервера и свободный UDP-порт (по умолчанию 51820).
3. Сохраните полученный `docker-compose.yml` на Linux-сервере с Docker Compose и `/dev/net/tun`, откройте UDP-порт в firewall и выполните `docker compose up -d --build`.
4. Дождитесь статуса «Онлайн». Создайте категорию и тариф с протоколом `AMNEZIAWG`, ценой, сроком, числом доступов и при необходимости лимитом трафика.
5. После покупки клиент скачивает `.conf` или открывает QR-код в кабинете → Мои доступы. Конфигурация импортируется в актуальную AmneziaVPN / AmneziaWG с поддержкой параметров AWG 2.0. Обычный клиент WireGuard не подходит.

AmneziaWG работает независимо от Remnawave и sing-box. Существующие тарифы `SINGBOX` продолжают выдавать VLESS / Shadowsocks / Trojan / Hysteria2; AmneziaWG-ноды в этот пул не попадают. Можно также выбрать конкретный протокол у обычного тарифа.

В сборке используются официальные `amneziawg-go` и `amneziawg-tools` с зафиксированными ревизиями в Dockerfile. Формат выдаваемой конфигурации — AWG 2.0; используются Jc/Jmin/Jmax, S1–S4 и уникальные H1–H4. Новые необязательные параметры AWG 3.x не требуются.

Один слот — отдельный профиль для одного устройства. Для нескольких устройств создайте тариф с нужным числом слотов.

## Данные и ограничения

- Закрытый ключ сервера и накопленные счётчики сохраняются в Docker-томе `awg-data`. Не удаляйте этот том при обновлении. Потерю/подмену серверного ключа панель обнаруживает и отклоняет регистрацию; восстановите том или создайте новую ноду и новые доступы.
- Приватные ключи клиентов хранятся в базе панели и выдаются только владельцу через авторизованный кабинет/бот. Агент получает публичный ключ, PSK и адрес; клиентский приватный ключ ему не передаётся. `.conf` и QR-код дают доступ к VPN, их нельзя публиковать.
- Агент работает в отдельной сетевой среде Docker, без host networking и без Docker socket. Требуются `NET_ADMIN`, TUN и IPv4 forwarding внутри контейнера.
- Выход в интернет — IPv4. Маршрут `::/0` в клиентском профиле предотвращает обход туннеля по IPv6; IPv6-интернет через эту ноду пока не предоставляется. Приватные сети, link-local/metadata и другие VPN-клиенты через ноду недоступны.
- На каждой ноде используется отдельная сеть `10.88.0.0/16`. Не подключайте профиль из сети с таким же адресным пространством.
- Политики обновляются примерно каждые 5 секунд. Срок действия и квота проверяются локально; квота имеет небольшое превышение на трафик между проверками (обычно 1 секунда, при сетевых таймаутах до 10 секунд).
- При недоступности панели действующие доступы продолжают работать до ближайшего срока окончания, исчерпания квоты либо истечения пятиминутного разрешения от панели. После этого нода закрывает доступ до успешной синхронизации. После перезапуска без связи с панелью доступ также закрыт.
- Счётчики сохраняются каждую секунду; при аварийном выключении возможна потеря последнего интервала. Обычный перезапуск сохраняет ключи и накопленный трафик.
- Порт и параметры обфускации фиксируются при создании ноды. Для их замены нужна новая нода и новые профили клиентов.
- Автобэкап базы панели не заменяет резервную копию `awg-data` на отдельном сервере ноды.

## Проверка

`npm run db:generate` и `npm run build` в backend, `npm run build` в bot и frontend.

На отдельной PostgreSQL-базе со схемой проекта:

```sh
cd backend
DATABASE_URL='postgresql://...' node --experimental-vm-modules tests/amneziawg-postgres.mjs
```

Обработчик файлов в боте проверяется командой `node bot/tests/amneziawg.mjs` из корня после сборки бота.

Тест проверяет параллельную обработку одного платежа, отсутствие частичной выдачи при нехватке мест, разделение протоколов, неоплаченные платежи, авторизацию агента, отсутствие приватного ключа в ответе агенту, закрепление ключа ноды, монотонные счётчики, квоты, блокировку, истечение срока и безопасное формирование конфигурации. Тест создаёт и удаляет свои записи; используйте отдельную базу.
