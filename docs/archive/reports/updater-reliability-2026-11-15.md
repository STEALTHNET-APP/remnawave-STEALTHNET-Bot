# Проверка зависимостей и загрузок обновлятора — 15 ноября 2026

[← Архив разработки](../README.md)

> Исторический документ. Описывает работу на дату составления; команды и пути конкретного стенда не являются общей инструкцией по установке или обновлению.

В Flood Роман сообщил, что для серверного меню пришлось отдельно устанавливать `make`. В установщике проекта такая попытка уже была, но её ошибка игнорировалась. Служба автообновления `make` не вызывает.

## Изменения

- Общая проверка make, Git, Python 3.9+, curl и CA-сертификатов для установщика проекта и установщика службы. Недостающие пакеты устанавливаются через apt-get/dnf/yum/apk. Результат проверяется; ошибка завершает установку до изменения конфигурации и контейнеров.
- Ограниченные повторы получения пакетов, ожидание блокировки apt и сетевые таймауты. Обновление всей ОС и переустановка Docker не выполняются.
- Установщик службы проверяет работающий systemd и использует обнаруженный Python. Повторная установка сохраняет настройки и больше не сообщает ошибочно, что расписание обязательно выключено.
- Проверка Docker daemon, возможностей Compose и свободного места в хранилище Docker до сборки и остановки сервисов. Rootless и недоступное локальное хранилище дают отдельную ошибку.
- До трёх попыток получения GitHub Release, исходников и образа nginx. GitHub API 401/403/404 и ошибка доверия сертификату не повторяются. Применение миграций и операции с рабочей БД не оборачиваются в повторные попытки.
- Понятные ошибки отсутствующей команды и превышения времени ожидания.
- Ошибка плановой очистки копий/образов сохраняется в журнале и cleanupWarning, не блокируя поиск обновлений. Контроль свободного места перед установкой остаётся обязательным.

## Проверки

`python3 -m unittest discover -s scripts/updater -p 'test_*.py' -q`: 59 тестов, успешно. Включены отсутствующий make, отказ пакетного менеджера, ложный успех установки, старый Python, временные и постоянные ошибки загрузок, недоступный/старый Docker, нехватка места, rootless и отказ до изменения развёртывания.

`bash -n install.sh scripts/updater/install.sh scripts/updater/dependencies.sh`: успешно.

Одноразовый `debian:bookworm-slim` на стенде: make изначально отсутствовал; скрипт установил необходимые пакеты, проверил Python 3.11.2 и GNU Make 4.3. Повторный запуск завершился успешно. Пакеты хоста не менялись. Установка пакетов через dnf/yum/apk на реальных ОС в этом прогоне не проверялась.

`STEALTHNET_UPDATER_DOCKER_TEST=1 python3 scripts/updater/docker-test.py` на стенде, отдельные контейнеры и тома:

- обновление с сохранением пользовательского nginx-конфига;
- полное обновление, миграция, фронтенд, консоль, копии БД и файлов;
- неудачная миграция до переключения;
- неудачный запуск до возобновления работы с возвратом БД, файлов, Git и локальных правок;
- ошибка после возобновления работы с сохранением новой записи и запретом отката старой БД.

Все пять сценариев прошли. Тестовые контейнеры и тома удалены штатной очисткой теста; рабочая панель не пересобиралась и не перезапускалась. Журналы на стенде: `/var/tmp/stealth-updater-reliability-20261115/`.

## Доставка

Исправления предназначены для следующего обновления из main или релиза, содержащего этот коммит. Установленные старые агенты не получают новый код от одной публикации в GitHub. Для заблокированного старого агента остаётся одноразовое восстановление по `docs/auto-update.md`. Установку новой версии на сервере Романа этот прогон не подтверждает.
