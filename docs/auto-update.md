# Обновления панели и бота

Начиная с 6.7.0 в настройках есть раздел «Обновления». Он показывает версию запущенного API, коммит, дату сборки, состояние установки и последние изменения. Коммит меняется при каждой сборке через установщик, Makefile или службу обновления; повторная сборка одного коммита не считается новой версией. `version.json` задаёт номер выпуска. Для следующего выпуска измените его и выполните `node scripts/sync-version.cjs`.

Автообновление выключено по умолчанию. Можно выбрать опубликованные стабильные релизы GitHub или `main`, задать час UTC и включить ежедневную установку. Черновики, prerelease и версии с более старой историей Git не устанавливаются. Канал `main` предназначен прежде всего для стендов. Ошибка проверки GitHub не останавливает работающую панель.

## Первичная установка

Нужны Linux с systemd, Python 3.9+, Git, Docker и Docker Compose с поддержкой `up --wait`. Поддерживается стандартный проект `stealthnet` из этого репозитория, с сервисами `postgres`, `api`, `broadcast-worker`, `bot`, `frontend`. Исходники должны быть в обычной ветке Git без собственных незакоммиченных файлов; `.env` и штатные игнорируемые настройки сохраняются. Docker rootless и нестандартные имена образов требуют отдельной настройки и этим установщиком не поддерживаются.

Сначала сохраните резервную копию БД штатным инструментом панели, обновите исходники до 6.7.0 и проверьте миграции текущей установки. Затем из папки проекта:

```bash
sudo bash scripts/updater/install.sh
export STEALTHNET_BUILD_COMMIT="$(git rev-parse HEAD)"
export STEALTHNET_BUILD_DATE="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
docker compose build api bot frontend
docker compose stop bot broadcast-worker api
docker compose up --no-deps --no-build --exit-code-from frontend frontend
docker compose up -d --no-deps --no-build --wait api
docker compose up -d --no-deps --no-build --wait bot broadcast-worker
```

Если nginx на хосте читает файлы из `/var/www/stealthnet`, при **первой** установке передайте эту папку:

```bash
sudo bash scripts/updater/install.sh /var/www/stealthnet
bash scripts/update-front-with-external-nginx.sh
```

Для существующей конфигурации служба сохраняет настройки: изменить путь можно в `/etc/stealthnet-updater/config.json` (`externalFrontend`), затем `sudo systemctl restart stealthnet-updater`. Это должна быть отдельная папка только для собранного фронтенда: её содержимое заменяется при обновлении. Для встроенного nginx `externalFrontend` должен быть `null`.

Откройте «Настройки → Обновления», выберите канал, сохраните настройки и нажмите «Проверить обновления». Номер сборки должен совпадать с `git rev-parse HEAD` на сервере. Если панель была собрана прямым `docker compose build` без переменных версии, пересоберите её с переменными выше.

Сам установщик проекта выставляет метаданные сборки, но отдельная служба устанавливается явно командой выше. Одного обновления файлов Git недостаточно — существующие контейнеры нужно пересобрать.

## Что происходит при обновлении

1. Служба получает код только из `STEALTHNET-APP/remnawave-STEALTHNET-Bot`. Произвольный репозиторий или команда через API не принимаются.
2. Проверяет историю Git, локальные изменения, соответствие запущенного API коммиту исходников и свободное место.
3. Собирает API, бот и фронтенд отдельно, пока старая версия работает. Обработчик рассылок использует образ API.
4. Останавливает API, бот и обработчик рассылок. Делает `pg_dump` и копию `.env`, Compose и nginx в `/var/lib/stealthnet-updater/backup-*` с закрытыми правами.
5. Обновляет исходники, фронтенд и контейнеры, проверяет здоровье API и запуск фоновых служб.
6. При ошибке восстанавливает исходники, образы и фронтенд предыдущей версии. База автоматически не восстанавливается и пользовательские записи не удаляются.

Во время установки есть короткий перерыв в работе. Уже существующие VPN-подключения Remnawave служба не меняет. Проверка запуска не заменяет функциональные тесты платежей и Telegram перед публикацией релиза.

**Ограничение первой версии:** изменения в `backend/prisma/`, `docker-compose*`, `nginx/`, `backend/docker-entrypoint.sh` и `scripts/updater/` устанавливаются вручную. Служба сообщит об этом, сохранив текущую версию работающей. Так автоматический откат кода не запускает старую версию поверх изменённой схемы БД. Собственные Compose overrides и изменённые исходники сначала нужно проверить вручную.

Служба работает на хосте, слушает Unix-сокет с правами `0600`; наружного порта и доступа веб-контейнера к Docker socket нет. Маршруты обновления доступны только полной роли `ADMIN`, даже если менеджеру выдали раздел настроек.

## Ошибки и восстановление

```bash
sudo systemctl status stealthnet-updater
sudo journalctl -u stealthnet-updater -n 100
sudo tail -100 /var/lib/stealthnet-updater/update.log
docker compose ps
```

Логи и резервные копии доступны только root и могут содержать служебные сведения. Не публикуйте их целиком. Старые резервные копии и образы не удаляются автоматически: контролируйте место и удаляйте только уже ненужные копии.

Если сервер или служба остановились посреди обновления, автоматический повтор заблокирован. В `/var/lib/stealthnet-updater/status.json` будут `recoveryRequired: true` и путь `backup`. Проверьте коммит, образы и БД. В папке резервной копии `images.json` хранит прежние образы; `settings.tar.gz` — настройки; `database.dump` — БД. Не восстанавливайте БД поверх новых пользовательских записей без отдельного решения.

После ручного восстановления остановите службу, сохраните `status.json` для диагностики и измените в нём `recoveryRequired` на `false`, `phase` на `idle`, затем запустите службу. Настройки расписания лежат отдельно в `settings.json`.

Чтобы отключить расписание, снимите переключатель в панели. Чтобы остановить всю службу, используйте `sudo systemctl disable --now stealthnet-updater` вне активного обновления.
