# Как обновить панель и бота

Эта инструкция относится к стандартной установке STEALTHNET на Linux-сервере с Docker. Обновление запускает владелец панели под основной учётной записью администратора.

## Выберите свою ситуацию

- **В панели есть рабочая кнопка «Обновить сейчас»** — начните с раздела 1.
- **У вас 6.8.0 или 6.8.1, обновление найдено, но кнопка заблокирована из-за `nginx/nginx.conf` или установки с тега** — раздел 2.
- **Служба обновления никогда не устанавливалась** — раздел 3.
- **Установка закончилась ошибкой или панель не открывается** — раздел 4.

## 1. Обычное обновление через панель

1. Откройте **Бэкапы**, создайте свежую копию базы данных и скачайте её на свой компьютер. Это дополнительная копия на случай проблем с сервером.
2. Откройте **Настройки → Обновления**.
3. Выберите источник:
   - **Получать только новые релизы** — опубликованные выпуски, например 6.8.2. Рекомендуем этот вариант для обычной работы.
   - **Получать последние обновления** — все новые изменения из `main`, включая изменения между релизами. Номер версии при этом может остаться прежним, а коммит изменится.
4. Нажмите **Сохранить настройки обновления**, затем **Проверить обновления**.
5. Если новая версия найдена, нажмите **Обновить сейчас**. Если её нет, не нужно ничего переустанавливать.
6. Дождитесь сообщения **«Обновление установлено»**. Сборка может занять несколько минут, на слабом сервере — дольше. Во время переключения версии панель и бот могут ненадолго быть недоступны. Не запускайте второе обновление и не перезагружайте сервер.
7. Перезагрузите страницу. В этом разделе проверьте новую версию и коммит. Откройте список клиентов и отправьте `/start` своему боту.

**Что означает «Сохранить правки и обновить»:** на сервере обнаружены дополнительные изменения исходников. Кнопка сохраняет их отдельно и устанавливает новую версию. Эти правки не будут автоматически добавлены в новую версию. Если вы заказывали собственные изменения у разработчика, сначала согласуйте их перенос. Пароли из штатного `.env` и конфиг домена сохраняются.

**Автоматическая установка по расписанию:** включите переключатель «Автоматически устанавливать обновления», выберите час UTC и сохраните настройки. Например, 03:00 UTC — это 06:00 по Москве. Пока переключатель выключен, панель только ищет обновления и предлагает их установить. Проверка выполняется при запуске службы и раз в 15 минут.

Уведомление **об обновлении страницы** в Mini App обновляет только открытый интерфейс. Оно не устанавливает новую серверную версию.

## 2. На старой версии кнопка заблокирована

В старом обновляторе были две ошибки: штатный конфиг домена считался мешающей правкой, а установка с тега Git не поддерживалась. В 6.8.2 они исправлены. Но старый заблокированный обновлятор не может сам установить своё исправление — нужен один запуск через SSH.

### Что понадобится

- SSH-доступ к **серверу панели**. Это не обязательно сервер Remnawave.
- Программа для подключения к серверу, например Termius, или терминал.
- Свежий скачанный бэкап из раздела **Бэкапы**.

Команды ниже выполняйте **на сервере после подключения по SSH**, не в консоли браузера и не в локальном терминале без подключения. Они рассчитаны на папку `/opt/remnawave-STEALTHNET-Bot`. Если панель установлена в другом месте, замените только этот путь.

### Запустите восстановление

Скопируйте блок целиком и нажмите Enter:

```bash
sudo bash <<'BASH'
set -euo pipefail
cd /opt/remnawave-STEALTHNET-Bot
test -f docker-compose.yml
git fetch https://github.com/STEALTHNET-APP/remnawave-STEALTHNET-Bot.git refs/tags/v6.8.2
update_repair_dir="$(mktemp -d /var/tmp/stealthnet-update-repair.XXXXXX)"
git archive FETCH_HEAD scripts/updater | tar -x -C "$update_repair_dir"
python3 "$update_repair_dir/scripts/updater/recover-update.py" --channel stable
BASH
```

При запросе пароля `sudo` ввод может не отображаться — это нормально. Ожидаемый ответ: **«Задание обновления запущено отдельно от SSH»**. Это означает, что процесс запущен, а не что обновление уже завершено. После этого закрытие SSH не прерывает установку.

Этот запуск устанавливает последний опубликованный стабильный релиз. Ранее выбранное расписание и источник следующих обновлений не меняются. Другие неизвестные локальные правки автоматически не удаляются.

### Посмотрите результат

```bash
sudo tail -n 40 /var/lib/stealthnet-updater/update.log
sudo cat /var/lib/stealthnet-updater/status.json
```

В `status.json` после успешной установки должно быть **`"phase": "success"`** и сообщение **«Обновление установлено»**. Пока там `building`, `rehearsal`, `backup`, `installing` или `verifying`, процесс ещё идёт. Во время восстановления панель может временно писать «Служба обновления недоступна» — дождитесь результата.

Если хотите смотреть журнал запуска в реальном времени:

```bash
sudo journalctl -fu stealthnet-update-recovery
```

Чтобы выйти из просмотра журнала, нажмите **Ctrl+C**. Само обновление продолжит работать.

Если показано `failed`, `recoveryRequired: true` или команда сообщила об ошибке, переходите к разделу 4. **Не запускайте `git reset --hard`, `git clean` и повторное восстановление наугад.**

## 3. Служба ещё не устанавливалась

Если вы раньше успешно пользовались автообновлениями, сообщение о недоступности службы не означает, что нужно устанавливать всё заново: сначала проверьте раздел 4.

При первой настройке нужен доступ к серверу. Служба устанавливается отдельно от веб-панели, после этого пересобираются контейнеры. Здесь важен способ установки Nginx: встроенный контейнер или отдельный Nginx на сервере.

Передайте администратору сервера [инструкцию первичной установки](auto-update-technical.md#первичная-установка). Не копируйте команды для другого способа установки. Если не знаете свой вариант, напишите в поддержку, как вы устанавливали панель.

## 4. Если что-то пошло не так

Сначала сохраните текст ошибки. Проверьте состояние на сервере:

```bash
cd /opt/remnawave-STEALTHNET-Bot
sudo systemctl status stealthnet-updater --no-pager
sudo journalctl -u stealthnet-update-recovery -n 40 --no-pager
sudo tail -n 60 /var/lib/stealthnet-updater/update.log
sudo cat /var/lib/stealthnet-updater/status.json
git status --short
docker compose ps
```

В обращении укажите установленную версию, выбранный источник обновлений и точный текст ошибки. Отправляйте журналы приватно: не публикуйте `.env`, пароли, токены, базы данных и архивы настроек. Если в статусе требуется восстановление, самостоятельно не меняйте этот флаг: сначала нужно проверить состояние базы и контейнеров.

Проверка не нашла обновление? В режиме релизов должны появиться новый опубликованный Release и его тег. Одного изменения `version.json` недостаточно. Если на сервере уже более свежий код, старый релиз поверх него автоматически не устанавливается.

## Что сохраняется и где лежит бэкап

Перед установкой служба сохраняет базу, исходники, настройки, загруженные файлы и сведения о старых Docker-образах. Копии находятся на сервере в `/var/lib/stealthnet-updater/backup-*`. По умолчанию срок — **3 дня**, его можно изменить в настройках обновлений.

Копии с сохранёнными локальными правками и копии, необходимые для восстановления после сбоя, не удаляются автоматически. Это отдельные копии: срок хранения в разделе **Бэкапы** управляет обычными SQL-архивами, а не резервными копиями автообновлятора.

При ошибке до возобновления работы служба может вернуть прежнюю версию. После возобновления записи новых пользовательских данных старая база автоматически поверх них не восстанавливается — требуется проверка администратора.

Подробности для администратора сервера: [устройство обновлятора и восстановление](auto-update-technical.md).
