# Получение сообщений Telegram через Webhook

По умолчанию бот продолжает работать через Long Polling. Для Webhook нужны обновлённые API и бот, публичный домен панели и действующий HTTPS-сертификат. Порт 8080 бота используется внутри сети Docker; открывать его в интернет не нужно.

## Включение

1. Обновите API, бот и frontend вместе по [инструкции обновления](auto-update.md). Перед обновлением создайте резервную копию.
2. В админке откройте **Настройки → Бот → Получение сообщений бота**.
3. Введите адрес своей панели с окончанием `/api/bot/webhook`, например `https://panel.example.com/api/bot/webhook`.
4. Поле секрета можно оставить пустым: панель создаст его сама. Если секрет уже сохранён, пустое поле его не меняет.
5. Нажмите **Включить Webhook**. Обычно переключение занимает несколько секунд; панель ждёт подтверждения до 30 секунд.
6. Нажмите **Проверить статус**. Должны совпасть режим Webhook в панели, адрес в Telegram и режим работающего процесса бота. Отправьте своему боту `/start` и проверьте открытие меню.

Если показано «Переключение не подтверждено», это не сообщение об успешной настройке. Проверьте, что контейнер бота запущен, домен доступен по HTTPS, а `BOT_TOKEN` у API и бота совпадает с токеном панели. Затем проверьте статус и повторите переключение. Сохранённый режим повторно проверяется ботом каждые 30 секунд. При ошибке загрузки конфигурации бот не включает другой режим самовольно.

## Возврат к Long Polling

Нажмите **Перейти на Long Polling**, подтвердите действие и проверьте статус. Бот сначала удалит webhook в Telegram, затем запустит опрос. Очередь обновлений Telegram при переключении не очищается.

## Обработка запросов

- Внешний запрос принимается только с сохранённым секретом Telegram. Внутренние запросы между API и ботом имеют отдельную проверку подлинности.
- Ошибка доставки возвращается Telegram как ошибка, чтобы он мог повторить запрос. Панель не делает немедленного повторного вызова при потере соединения.
- Повтор одного `update_id` объединяется с уже выполняющейся обработкой. Успешно обработанные ID сохраняются в памяти процесса на сутки, максимум 50 000 записей. Этот кэш не переживает перезапуск и не заменяет идемпотентность платёжных обработчиков.
- События одного пользователя обрабатываются по порядку, включая `pre_checkout_query`. Разные пользователи могут обрабатываться параллельно.
- Ответы Bot API отправляются обычными запросами с проверкой результата. Webhook Reply не включён: по [документации grammY](https://grammy.dev/guide/deployment-types#webhook-reply) он не позволяет получить результат и проверить успешность вызова.
- Для главного меню профиль, подписки и доступные триалы собираются одним запросом к API. Список подписок не кэшируется отдельно, поэтому переименование и изменение автопродления видны при следующем запросе.

Webhook не гарантирует фиксированное время ответа: оно зависит от Telegram, сети, базы данных и Remnawave. Реальную задержку нужно измерять на своей установке.
