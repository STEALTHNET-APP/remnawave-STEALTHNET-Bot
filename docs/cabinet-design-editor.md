# Редактор оформления клиентского кабинета

Откройте **Настройки → Темы → Открыть редактор** или `/admin/cabinet-design`.
Раздел доступен администратору; менеджер не может читать и менять настройки редактора.

## Как изменить оформление

1. Выберите готовый пресет: Графит, Бумага, Океан, Лес, Тушь или Редакция.
2. Во вкладке **Цвета** выберите режим для клиентов: всегда тёмный, всегда светлый или как в системе. Для системного режима настройте обе палитры.
3. Во вкладке **Элементы** настройте шрифт, размер текста, скругления, отступы, ширину, кнопки и анимации.
4. Посмотрите образец на телефоне, планшете и компьютере. В переключателе экрана доступны подписки, тарифы и вход.
5. Нажмите **Сохранить черновик**, чтобы продолжить позже. Клиенты черновик не видят.
6. Нажмите **Опубликовать**, когда готовы. Откройте настоящий кабинет и проверьте результат. Открытые клиентские вкладки подхватывают стиль при возвращении фокуса или в течение минуты; перезагрузка применяет его сразу после загрузки настроек.

Предпросмотр содержит демонстрационные данные и показывает стиль на образце. Это не копия аккаунта: реальная компоновка зависит от выбранной темы кабинета. Редактор меняет общие параметры оформления, но не порядок блоков, тексты, функции кнопок, тарифы и подписки. Произвольные HTML, CSS и JavaScript не принимаются.

При включённом опубликованном стиле старый пользовательский переключатель оформления скрывается. Админский интерфейс и лендинг редактор не изменяет.

## Как вернуть прежний вид

Во вкладке **История** найдите нужную версию и нажмите **Восстановить в черновик**. Проверьте её и нажмите **Опубликовать**. Хранятся 12 предыдущих публикаций.

Чтобы полностью убрать настройки редактора, во вкладке **Элементы** выключите **Применять это оформление** и опубликуйте. Вернётся исходная тема кабинета. Демонстрационный образец при выключенном оформлении не воспроизводит исходную тему.

**Шаг назад** отменяет локальную правку. **Отменить изменения** возвращает последнее загруженное состояние; **Отменить черновик** удаляет сохранённый черновик и возвращает опубликованный стиль.

## Перенос и ошибки

**Экспорт** сохраняет JSON текущего стиля. **Импорт** загружает такой файл только в предпросмотр — затем его нужно сохранить или опубликовать. Максимальный размер 128 КБ.

Неверный HEX или некорректные параметры блокируют сохранение и публикацию. Предупреждение о низком контрасте помогает подобрать читаемые цвета.

Если другой администратор уже сохранил изменения, редактор не перезапишет их. Экспортируйте свой вариант, отмените локальные изменения, загрузите актуальную версию и при необходимости импортируйте свой файл.

## Хранение и проверка

Данные хранятся в существующей таблице `system_settings`, ключ `cabinet_design_v1`. Миграция базы не требуется. Черновик, опубликованная версия и история разделены. Публичный endpoint отдаёт только опубликованный стиль. Запись использует номер ревизии и атомарную проверку предыдущего значения.

Проверки: сборка frontend/backend; `node --test backend/tests/cabinet-design.test.mjs` после сборки backend. Интеграционный тест `backend/tests/cabinet-design.integration.mjs` запускается только с отдельной пустой тестовой PostgreSQL, именем хоста `cabinet-design-test-db` и тестовым JWT_SECRET. Перед запуском примените Prisma schema к этой тестовой базе. Не используйте рабочую базу.

На стенде 29.10.2026 проверены: API-права, валидация, конкурентное сохранение, отделение черновика, публикация, история и отключение. В браузере проверены сохранение после перезагрузки, неверный HEX, отмена правки, публикация тёмного/светлого пресета, реальный кабинет и мобильные тарифы, редактор при ширине 390 px, скрытие пользовательского переключателя. Исходное оформление после проверки восстановлено. Платежи и покупки не выполнялись. Все варианты старых тем отдельно не проверялись.

## Резервная копия стенда

Перед выкладкой сохранены рабочая база, frontend, исходный и собранный `app`, а также снимок API-контейнера:
`/var/backups/stealthnet-cabinet-designer-20261029`.

Откат API и frontend:

```sh
bash /var/backups/stealthnet-cabinet-designer-20261029/rollback.sh
```

Скрипт не откатывает рабочую базу и не удаляет операции пользователей; ключ оформления останется неиспользуемым. Скрипт прошёл синтаксическую проверку, полный аварийный откат после этой выкладки не запускался. Возврат оформления через интерфейс проверен.

При первой выкладке обнаружены права 600 на публичных файлах после наследования `umask`: это вызвало кратковременный 403 frontend. Скрипт выкладки исправлен: файлы публикуются с правами 644; повторная проверка сайта прошла.

На старом стенде API расширен отдельным модулем, без замены всей серверной сборки и без git reset/pull. Исходники модуля сохранены в проекте стенда. Изменения этой задачи в GitHub не отправлялись.
