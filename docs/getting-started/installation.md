# Установка и первый запуск

[← Начало работы](README.md)

Эта инструкция предназначена для новой установки на отдельный Linux-сервер. Если панель уже работает, используйте [обновление](../auto-update.md), а не повторный запуск установщика.

## Подготовьте сервер

Понадобятся доступ по SSH с правами root или sudo, домен панели, доступ к Remnawave и токен бота из BotFather, если нужен Telegram-бот. Направьте DNS-запись домена на сервер. Для встроенного nginx порты 80 и 443 должны быть доступны извне и не заняты другим веб-сервером.

Для небольшой установки разумная стартовая конфигурация — 2 vCPU, 4 ГБ RAM и 40 ГБ SSD. Это ориентир, а не гарантия ёмкости: нагрузка и потребление места зависят от числа клиентов, фоновых задач и хранения бэкапов.

Команды ниже выполняются в SSH-терминале **сервера панели**, под root. Блок подготовки рассчитан на Debian/Ubuntu с `apt`. На другом дистрибутиве установите те же зависимости штатным менеджером пакетов.

```bash
apt update
apt install -y git make curl ca-certificates python3
```

Если Docker ещё не установлен, установите Docker Engine и Compose v2. На отдельном новом сервере можно использовать скрипт Docker, предложенный установщиком проекта:

```bash
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
sh /tmp/get-docker.sh
```

Проверьте зависимости:

```bash
docker version
docker compose version
```

Обе команды должны завершиться без ошибки. При ошибке Docker сначала исправьте его установку.

## Скачайте релиз

Проверьте [список релизов](https://github.com/STEALTHNET-APP/remnawave-STEALTHNET-Bot/releases/latest). Пример ниже устанавливает `v7.0.2`. Для более нового выпуска замените тег его точным именем.

```bash
cd /opt
git clone --branch v7.0.2 https://github.com/STEALTHNET-APP/remnawave-STEALTHNET-Bot.git
cd remnawave-STEALTHNET-Bot
bash install.sh
```

Установщик запросит домен, режим nginx, параметры Remnawave, данные администратора и Telegram-бота. Затем соберёт и запустит сервисы. Это может занять несколько минут; дождитесь завершения.

**На вопрос об удалении старых данных выберите `N`.** Очистка удаляет базу и не нужна для обычной установки или устранения ошибки пароля. Если в каталоге уже есть `.env` или данные работающего сервиса, остановитесь и используйте инструкцию по обновлению.

При выборе собственного reverse proxy настройте его отдельно по [конфигурации](configuration.md).

## Готовые Docker-образы

Это отдельный режим для администратора сервера. Установщик и автообновление из панели по-прежнему собирают проект из исходников. Переключать рабочую установку на готовые образы необязательно.

Нужны Docker Compose V2 с `--wait`, Python 3, Git и настроенный `.env`. Для встроенного nginx сертификат и конфигурация должны уже существовать. Для внешнего nginx задайте `FRONTEND_OUT_DIR` — каталог сайта из его конфигурации.

Перейдите на нужный коммит проекта и дождитесь успешного workflow **Publish Docker images** для него. Запустите:

```bash
bash scripts/run-prebuilt.sh
```

Скрипт скачивает `ghcr.io/stealthnet-app/stealthnet-{api,bot,frontend,console}:sha-<полный коммит>`. У всех четырёх образов проверяется ревизия. Если загрузка или проверка не прошла, работающие контейнеры не меняются. Локальный `docker-compose.override.yml` сохраняет порты, тома и остальные настройки. Режим запуска записывается в `.env`, поэтому `docker compose ps`, `logs` и `stop` продолжают работать с той же конфигурацией.

Перед заменой контейнеров существующая база сохраняется в `backups`, а настройки и список прежних образов — в отдельный каталог `backups/prebuilt-*`. При неудачном запуске автоматического восстановления базы нет: путь к копии остаётся в выводе команды. Восстанавливайте её по [инструкции резервного копирования](../backup-retention.md), предварительно остановив запись в базу.

Для следующего обновления сначала перейдите на проверенный коммит, затем повторите команду или выполните `make pull-update`. Обновление через панель в этом режиме останавливается с пояснением: оно не должно незаметно возвращать сервер к сборке из исходников. Чтобы вернуться к исходникам, восстановите `COMPOSE_FILE` из сохранённого `.env`, затем выполните штатное обновление с резервной копией.

Если GitHub Packages закрыты, сначала выполните `docker login ghcr.io` с токеном, у которого есть доступ `read:packages`. Секреты в команду запуска и репозиторий не добавляйте.

## Проверьте запуск

Из каталога проекта выполните:

```bash
docker compose ps
docker compose logs --tail=100 api bot
```

Откройте `https://ваш-домен/admin`, войдите с данными установки и проверьте подключение Remnawave. Если настроен бот, отправьте ему `/start`. В разделе **Бэкапы** создайте и скачайте первую копию базы.

Frontend собирает и копирует статические файлы, после чего его контейнер может завершиться успешно — он не обязан постоянно работать как API и бот. При ошибке запуска переходите к [решению проблем](../operations/troubleshooting.md).
