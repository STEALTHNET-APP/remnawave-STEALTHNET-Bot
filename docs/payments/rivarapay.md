# RivaraPay

[← Платёжные системы](README.md)

RivaraPay принимает разовые платежи за подписки и продления, подарки, прокси, sing-box, дополнительные опции и пополнение баланса. Счёт создаётся в RUB. Покупатель выбирает способ оплаты на странице RivaraPay; доступны только методы, подключённые к его кассе.

## Подключение

1. В кабинете RivaraPay создайте API-ключ магазина с правами `payments:read` и `payments:write`.
2. Откройте **Настройки → Платёжные системы → RivaraPay**. Введите API-ключ и секрет уведомлений, включите провайдера.
3. Скопируйте адрес уведомлений из карточки — `https://ваш-домен/api/webhooks/rivarapay`. Добавьте его в RivaraPay с событиями `payment.paid`, `payment.canceled`, `payment.expired`, `payment.refunded`.
4. Для франшизного магазина раскройте соответствующий раздел и укажите тип и адрес филиала, Telegram ID владельца. Username владельца необязателен. Данные покупателя панель передаёт отдельно: Telegram ID или email.
5. Сохраните настройки. Название кнопки и положение в списке способов оплаты редактируются в общем списке провайдеров выше.

Не используйте номер кассы вместо Telegram ID владельца филиала. Если у покупателя нет ни email, ни Telegram ID, перед оплатой потребуется привязать один из них в профиле.

## Проверка

Для тестовой кассы используйте ключ с префиксом `test_` и включите **Тестовый режим**. Панель проверит подпись уведомления, сумму, валюту, номер заказа и состояние платежа через API. Тестовые события записываются в журнал, но не начисляют баланс и не выдают реальные подписки. Локальный платёж остаётся ожидающим; результат проверки виден в журнале уведомлений.

Для приёма денег нужны ключ `live_` и выключенный тестовый режим. Режим ключа и переключателя должны совпадать. Не меняйте ключ и режим, пока есть незавершённые счета прежней кассы: их уведомления проверяются действующими реквизитами.

Возврат пользователя со страницы оплаты не подтверждает оплату. Баланс начисляется только после проверенного уведомления. Выдача оплаченной покупки выполняется отдельной очередью. Если она не завершилась, платёж остаётся оплаченным, а причина отображается в карточке платежа для администратора.

## Ошибки и повторные уведомления

Повторные уведомления не начисляют баланс и не создают выдачу второй раз. Если API RivaraPay или база временно недоступны, обработчик возвращает ошибку, чтобы провайдер повторил доставку.

При потере ответа на создание счёта запись заказа сохраняется. Проверьте этот заказ в кабинете RivaraPay перед новой попыткой, чтобы не оплачивать два счета. Последующее подписанное уведомление может подтвердить такой заказ даже без сохранённого внешнего ID.

В админке откройте **Журнал webhook** и выберите `rivarapay`. Если провайдер исчерпал повторы, после устранения причины повторите доставку из его кабинета: исходная подпись действует только пять минут.

## Возвраты

Возврат оформляется в кабинете RivaraPay. Полный подтверждённый возврат меняет статус платежа на `REFUNDED`, отменяет начисление за пополнение и денежные реферальные начисления из `ReferralCredit`. Повторное уведомление не повторяет списание.

Частичный возврат требует ручной сверки суммы. Выданную подписку, устройства и бонусные дни администратор проверяет отдельно. Выдача, ещё ожидающая обработки, блокируется; если выдача уже выполняется, уведомление будет обработано повторно после её завершения. Автоматический повтор выдачи возвращённой покупки недоступен.

Интеграция обрабатывает обычные возвраты `payment.refunded`. Возвраты конвертированных платежей (`refund.succeeded`) требуют ручной сверки. Автоплатежи и фискальные чеки через RivaraPay в этой интеграции не реализованы.
