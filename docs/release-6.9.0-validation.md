# Проверка 6.9.0

База ветки: `417d126` (`main` после PR #253). Список изменений собран относительно `v6.8.2` в [описании релиза](release-6.9.0.md).

## Выполнено 29.10.2026

- Production-сборки frontend, backend и бота с Node.js 24.14.1.
- 56 проверок бота: меню, устройства, выбор покупки, поддержка и обработчики продления.
- В `bot/tests/renewal-flow.mjs` выполняется настоящий обработчик callback из исходников бота. Запуск polling исключён; API и Telegram-ответы заменены тестовыми. Проверены обе длительности тарифа, истёкшие подписки, несколько подписок при отключённых мультиподписках, кулдаун, дополнительные устройства, устаревший `add`, чужой ID, ошибка API и конвертация самостоятельного триала. До запроса оплаты доходит ID выбранной подписки.
- Пять backend-проверок контракта редактора оформления и две проверки публичной конфигурации, включая `cabinetDesign=modern` и применение в браузере. Для `cabinet-public-config.test.mjs` нужен `--experimental-test-module-mocks`.
- Семь frontend-проверок навигации и политики тем; отдельные проверки выбора варианта Mini App и Telegram viewport.
- В браузере на локальной production-сборке с тестовыми данными и имитацией Telegram SDK: главная, тарифы, смена 30/90 дней и настройки. Ширина 390 и 320 px; горизонтального переполнения нет, ошибок консоли нет, нижняя навигация учитывает safe area. Выбран `modern`, Mini App определяется, используется новый интерфейс.
- Проверено совпадение версии в `version.json`, трёх package.json и lock-файлах.

## Границы проверки

Реальные списания, отправка сообщений в Telegram и выдача VPN-доступа не выполнялись. Автоматические проверки запроса оплаты не заменяют тест эквайринга. Mini App в этом проходе проверялся через имитацию Telegram SDK, а не в приложениях Telegram на физических iOS/Android.

Новый пакет этой ветки на рабочий стенд не выкладывался. Проверки и резервные копии ранее опубликованной админки описаны в `admin-redesign-stand.md`, `admin-polish-20261029.md` и `admin-search-shortcut-20261029.md`.

CloudPayments (#251) добавлен отдельным изменением от базы `ff64bac`. Порядок подключения и границы автоматической проверки описаны в `cloudpayments.md`. Терминал CloudPayments с тестовыми реквизитами не подключался; проверка реального эквайринга остаётся обязательной перед включением рабочих списаний. Релиз остаётся черновиком.


## CloudPayments — дополнение к #251

Проверки выполнены с Node.js 24.14.1. Собраны backend, frontend и бот; Prisma Client сгенерирован из обновлённой схемы.

- 17 интеграционных сценариев в `backend/tests/cloudpayments.integration.mjs`: HMAC, проверка заказа, параллельные Check/Pay, согласие, платный триал, потерянные ответы при создании VPN-профиля и плана списаний, изменение цены и устройств, отказ и восстановление после льготного срока, полные/частичные возвраты, отмена, режим одной подписки, объединение аккаунтов, ручное продление, смена тарифа, повторное открытие счёта, чужой период тарифа и лимит устройств, повтор запроса возврата. Полный проход из 15 сценариев завершился успешно; после последних правок отдельно повторены затронутые сценарии и добавлены ещё два.
- PostgreSQL работал в отдельном временном контейнере на стенде; использовалась только база `cloudpayments_test`. Внешние API CloudPayments и Remnawave заменены имитациями. Рабочие аккаунты, деньги и VPN-профили не использовались.
- Миграция `20261029190000_cloudpayments` применена к схеме из `ff64bac` в отдельной базе `cloudpayments_migration_test`. Существующий тестовый клиент и баланс 77,25 сохранены; проверен уникальный индекс действующего автоплатежа на подписку.
- 17 проверок бота: меню, доступность способов оплаты и реальные callback-обработчики продления/платного триала с тестовым API. После чистки обработчика повторены все 14 сценариев `renewal-flow.mjs`.
- Три набора регрессионных проверок backend: дополнительное устройство, продление вторичной подписки, объединение Remna-профилей. Три проверки публичной конфигурации, включая доступность CloudPayments без раскрытия API Secret.
- Настоящая страница оплаты проверена в браузере: обычный счёт, условия триала, отказ без согласия. При ширине 390 и 320 px горизонтального переполнения нет; ошибок JavaScript не обнаружено. Данные карты не вводились.

Тесты не подтверждают работу конкретного торгового терминала, 3-D Secure или банковских списаний. Интеграция выключена по умолчанию. Порядок проверки терминала перед включением — в `cloudpayments.md`. Черновик релиза не опубликован; рабочая установка в этом проходе не обновлялась.
