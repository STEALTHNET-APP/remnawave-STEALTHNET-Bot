# PR #293 и #301: исправления перед слиянием

## Подписки — #293

- Добавлены смена основной подписки, редактор записи в БД и восстановление отсутствующего основного слота.
- Смена основной подписки и обновление полей клиента выполняются одной транзакцией. Переносятся UUID, тариф (включая `null`), цена и настройки автопродления выбранной подписки.
- Редактирование дополнительной подписки не меняет основную. `syncToClient` для дополнительной подписки отклоняется; для смены основной используется отдельное действие.
- Проверяется занятость Remna UUID в обеих таблицах: `Client` и `Subscription`. Конкурирующие изменения используют блокировки владельца, строк и UUID.
- Неактивированный или переданный другому владельцу подарок нельзя сделать основным. Полученный подарок текущего владельца разрешён.
- Автовосстановление не стирает отдельную legacy-привязку. Очистка ссылки после удаления разрешена только для UUID явно удалённой подписки.
- При изменении UUID сбрасывается кеш прежнего VPN-профиля. Простое переименование не сбрасывает промокод и состояние уведомлений автопродления.
- Новые операции изменения основной подписки и редактирования БД доступны только администратору.

## Очистка триалов — #301, issue #294

- Автоудаление по умолчанию выключено. Администратор задаёт срок хранения после окончания бесплатного триала.
- Отбираются только записи с явной связью с бесплатным триалом и известным истёкшим сроком. Импортированные, платные, подарочные и legacy-профили с неизвестными данными сохраняются.
- Любой платёжный счёт защищает аккаунт: оплаченный, ожидающий оплаты, неудачный или возвращённый. Наличие других услуг, соглашений автоплатежей, открытых обращений и положительного либо отрицательного баланса также исключает удаление.
- Клиент и его подписки блокируются и повторно проверяются внутри транзакции. Вставка нового платежа не может обойти блокировку клиента; уже созданный счёт исключает удаление.
- Перед удалением проверяются владелец и актуальное состояние Remna. Неизвестный срок, действующий профиль или недоступность Remna останавливают удаление.
- После ответа на удаление дополнительно проверяется отсутствие профиля в Remna. При ошибке локальная запись сохраняется для повторной обработки. Повторный запуск сверяет уже отсутствующие удалённые профили.
- В интерфейсе доступны проверка без удаления, ручной запуск с подтверждением и отдельные счётчики удалённых, пропущенных и ошибочных записей.

## Проверки

- 37 интеграционных тестов на PostgreSQL 16, включая конкурирующие изменения UUID, одновременную оплату и очистку, потерянный ответ Remna и повторный запуск. Ответы Remna моделировались; реальные VPN-профили не использовались.
- 56 тестов правил подписок, выбора продления, платёжных намерений и триалов.
- Сборки API и frontend; проверка PWA precache-графа: 268 файлов.
- PostgreSQL и тестовый процесс запускались на стенде в отдельной внутренней Docker-сети, с пустой временной БД, без реквизитов рабочей базы и Remna. После прогона контейнеры и сеть удалены.

Рабочие клиенты не удалялись, автоудаление на стенде не включалось. Этот набор изменений не выпускает новый релиз и не обновляет установленный стенд автоматически.
