# Admin interface design

The admin works with clients, tariffs, support requests and server state. The visual baseline is the approved cabinet: Onest typography, neutral charcoal and warm white surfaces, restrained accent, clear borders and compact operational data.

The modern shell is the default; Old classic remains available through the appearance menu. Appearance is personal browser state and is independent of client configuration. CSS is scoped to the admin route and modern appearance. Existing page components, backend contracts and permission filtering remain in use.

The collapsed rail keeps its quick links stationary while the full navigation expands beside it. Pinning reserves space; mobile uses a modal navigation drawer. Controls retain keyboard focus indication and dialogs use the existing Radix focus management. Reduced-motion users receive minimal transitions.

The supplied kill-ai-slop, stop-design-slop, anti-slop, taste-skill, hallmark, impeccable, design-slop, better-frontend and beuniq guides informed the work: preserve real product tasks, use actual data, remove decorative card nesting, avoid gratuitous gradients, retain readable form labels and check alternate states. Existing cabinet styling takes precedence over unrelated marketing-page examples.

Validated on the stand: dark/light appearance, classic switching, live data, tariff form, tickets, settings and search. Follow-up audit covered all 45 navigation entries and browser viewports of 360×800, 390×844 and 1440×960. Mobile drawer placement, overflowing controls, referral graph panels, dashboard density and inherited Tailwind color aliases were corrected. This is browser viewport testing, not physical-device certification. Financial operations, broadcasts and destructive actions were not exercised. See ../docs/admin-redesign-stand.md for deployment evidence and rollback.
